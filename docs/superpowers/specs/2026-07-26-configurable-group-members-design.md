# 可配置群组成员设计

## 背景

现有协作群组只能从五个写死角色中勾选成员。角色名称、人设、职责、产出物都定义在主进程常量中；群组只保存角色 ID 数组，并在发送消息时为整条接力链选择一个公共模型。群组没有接入文件系统技能。

本次改造让用户在创建群组时逐个创建和配置成员，同时保留现有五个角色作为快捷模板。每个成员拥有独立模型、技能和人设。消息中的有效成员提及显示为高亮 `a-tag`，编排层增加明确的循环检测与终止原因。

## 目标

- 创建群组时可以新增、编辑、删除和排序成员。
- 可以从五个内置角色模板快速添加成员，也可以从空白成员开始。
- 每个成员独立配置名称、职责、产出物、人设、头像颜色、模型和技能。
- 输入框提供当前群成员的 `@` 候选；有效提及在用户消息和 Agent 消息中高亮显示。
- 接力按当前成员自己的模型和技能执行。
- 允许同一成员在一条接力链中参与两次；第三次参与时终止，兼顾一次正常返工。
- 检测重复接力边，避免 A、B 之间持续往返；保留最大跳数作为最后保险。
- 循环、成员次数和跳数上限都向界面报告明确原因。
- 功能尚未发布，群组成员数据只保留单一 `GroupMember[]` 形态。

## 非目标

- 不做跨群共享的成员模板库。
- 不做群组创建后的成员编辑。
- 不为成员配置 MCP、联网或写文件能力。
- 不改变群聊“消息即 Markdown 文档”的产出模式。
- 不把成员拆成独立数据库表。

## 数据模型

新增共享类型：

```ts
interface GroupMember {
  id: string
  name: string
  color: string
  duty: string
  deliverable: string
  persona: string
  /** models 表的行主键，不是供应商侧 modelId */
  modelRowId: string
  skillIds: string[]
}

type GroupMemberDraft = Omit<GroupMember, 'id'>

interface CreateGroupInput {
  name: string
  members: GroupMemberDraft[]
}
```

`SessionSettings.members` 只接受 `GroupMember[]`。功能尚未发布，不保留 `string[]` 读取分支。成员保存在 `conversations.settings` JSON 中，因为成员仅属于一个群、数量小、随群整体创建和删除。

成员 ID 由主进程在创建群组时生成 ULID，是消息 `author`、结构化提及和接力路由的稳定身份。渲染层草稿可以有仅用于 `v-for` 的临时键，但不通过 IPC 充当持久 ID。主进程不接受调用方指定成员 ID，并在生成后保证群内唯一。

名称只用于展示，群内必须唯一。成员保存 `models.id` 行主键 `modelRowId`；执行时先用 `getModel(member.modelRowId)` 取得模型行，再使用模型行的 `providerId` 与供应商侧 `modelId` 调用 `getLanguageModel()`。技能继续保存文件系统技能名称，保持现有单一事实来源。

内置模板仍由主进程提供，但模板不携带模型和技能。用户把模板加入群组后，会得到一份可修改的成员草稿和新的成员 ID。

## 成员读取与发送契约

`conversations.settings` 来自 JSON，运行时仍按不可信数据处理。共享 guard 只有在 `members` 是非空对象数组、每个对象都具备完整 `GroupMember` 字段且成员 ID 是 ULID 时才判定为已配置；归一化函数直接返回该 `GroupMember[]`。字段缺失、非法成员 ID、混合数组、`string[]` 或 `members` 缺失都归一化为空数组，不猜测、不补造成员。

`GroupSendInput` 只包含 `conversationId` 和 `text`。输入区不提供公共模型选择器；每一棒始终使用成员自己的 `modelRowId` 和 `skillIds`。群组没有合法成员时，用户消息仍作为留言保存，但不会启动 Agent，也不会崩溃。

## 创建群组界面

创建弹窗拆成三个职责明确的组件：

- `CreateGroupModal.vue`：管理群名、成员草稿列表和提交。
- `GroupMemberList.vue`：展示、排序、编辑和删除已添加成员。
- `GroupMemberEditor.vue`：编辑一个成员的字段、模型和技能。

弹窗先展示群名和成员列表。用户可以选择内置模板或“空白成员”添加，随后在成员编辑区配置。技能选择复用现有的文件系统技能来源和搜索语义，但只允许勾选非内置技能；群组没有项目上下文，不自动启用设计类内置技能。

提交前校验：

- 群名非空。
- 至少一个成员。
- 成员名称先 `trim`，再校验名称和人设非空。
- 群内成员名称唯一。
- 名称长度为 1–24 个字符，禁止换行及 `@[]()`，并禁止使用保留名称“用户”。
- 每个成员选择了仍然可用且支持 tools 的模型。
- 技能数组由主进程过滤为当前存在且非 builtin 的技能名；不存在或内置技能不报错、不保存。已消失的技能在编辑状态显示警告并允许用户移除。

## 结构化提及

输入框使用 Antdv Mentions 提供候选。群组发送和存储使用稳定的规范文本：

```text
@[产品经理](member:01ABC...)
```

- 把候选选择转换成规范文本。
- 从用户消息中找到第一位有效成员。
- 从 Agent 输出末尾五行找到下一位有效成员。
- 把规范提及转换成给模型阅读的 `@成员名`。
- 把规范提及转换成消息展示所需的文本/成员片段。

为支持用户手动输入和模型自然输出，也接受精确匹配的 `@成员名`。这是当前提及协议的一部分，不是旧数据兼容分支。解析时按名称长度降序并要求完整边界，不再使用 `startsWith`。同名校验保证名称到成员的映射唯一。规范文本不需要名称转义，因为创建校验禁止会破坏语法的字符；成员 ID 只接受主进程生成的 ULID。

代码围栏和行内代码中的 `@` 不高亮，也不作为接力指令。用户消息使用提及片段组件直接渲染；Agent Markdown 在进入 Comark 前把有效、非代码区的规范提及和精确 `@成员名` 都转换成已注册的安全行内 mention 组件，由 Vue 组件输出 `a-tag`，不注入任意 HTML。

## Agent 执行

每一棒根据当前 `GroupMember` 解析：

- `getModel(member.modelRowId)` 校验模型存在、启用且支持 tools。
- 使用返回模型行的 `providerId` 和供应商侧 `modelId` 创建语言模型。
- `scanSkills()` 后按 `member.skillIds` 过滤。
- 把所选技能目录加入本地读取范围。
- system prompt 中加入 `skillCatalog`。
- tools 中加入 `buildSkillTools`，保持现有渐进披露语义。

本地工作区授权仍按群组 conversationId 共享；成员技能仅对该成员这一棒可见。

## 循环保护

每条接力链维护：

- `visits: Map<memberId, number>`：成员开始执行前递增；第三次参与时终止。
- `edges: Map<fromId→toId, number>`：同一有向接力边第二次出现时终止。
- `MAX_HOPS = 8`：作为未覆盖情况的最终保险。

允许 `A → B → A`，因为 A 的第二次参与可用于一次返工；如果随后再次形成 `A → B`，重复边保护会立即终止，不继续到八跳。

Agent 提及自己时忽略该提及并继续查找同一末尾片段里的其他成员；若没有其他有效成员则正常结束。末尾五行只要出现 `@用户` 就优先正常结束，即使同时出现成员提及。多个非自身成员提及时取文本顺序中的第一个。

新增流事件：

```ts
{
  type: 'chain-stopped'
  reason: 'cycle-detected' | 'member-limit' | 'hop-limit'
  message: string
}
```

正常无人接棒或 `@用户` 仍发送 `chain-done`。用户点击停止仍按 aborted 处理。界面对 `chain-stopped` 清理运行状态并展示服务端给出的中文原因。

## 错误处理

- 新建群组的输入全部在主进程再次校验，渲染层校验不作为安全边界。
- 主进程拒绝空成员、重复名称、非法或保留名称、无效模型行以及不支持 tools 的模型。
- 成员模型或供应商失效时，当前成员消息标记为 error，并报告具体成员与原因。
- 技能被卸载时忽略该技能并继续执行，system prompt 中只展示实际存在的技能。
- `members` 缺失、损坏或不是完整对象数组时按空群处理；用户消息只留言，不启动 Agent。
- 非法或已删除成员的提及只作为普通文本，不启动接力。
- 任何异常都必须清理 `running` 状态，允许用户再次发送。

## 测试

- 单元测试成员归一化、创建输入校验，以及 `string[]`/损坏对象数组不被接受。
- 单元测试规范提及、精确自然名称提及、代码区排除、重名和边界字符。
- 单元测试自我提及、`@用户`、成员第三次参与、重复边和最大跳数。
- 单元测试每个成员解析独立模型和技能。
- Vue 组件测试创建成员、字段校验、模型/技能配置及提及 tag 渲染。
- 最终运行 `pnpm typecheck && pnpm lint && pnpm vitest run`。
