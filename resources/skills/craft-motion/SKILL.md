# 动效纪律

时长和曲线不是审美方向,是手感的正确性——下面的数值默认全部生效。StyleBrief 只在
一处介入:它的原文明确点名了节奏气质(如"从容、舒展"或"轻快、利落")时,可以把时长
表整体上调或下调约 30%,但曲线纪律、性能规则和"该不该动"的判断不随主题改变。

## 先问该不该动

有实证:关于"动画帮助理解"的研究,把对照组做严格之后,动画**并不优于静态图**。
唯一站得住的用途是**实时的空间或时间重定向** —— 页面切换、容器展开、
视角变化、进度反馈。

所以:**用户在空间、时间或状态中移动时才动**。
不要为了"教会他""显得高级""填补沉默"而动。

## 时长

| 时长 | 用途 |
| --- | --- |
| 50–100ms | 即时反馈(按下、切换、悬停) |
| **120ms** | 界面微反馈的默认值 |
| **200ms** | 元素进场(弹层、抽屉、下拉) |
| **140ms** | 元素退场 |
| 300–500ms | 跨屏转场、容器变形 |
| >500ms | 只留给跨屏的、分阶段的转场 |

**进场和退场不对称。** 退场要更快 —— 用户已经决定关掉它了,拖泥带水只会烦人。

## 一条曲线用到底

```css
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);
```

- 内置的 `ease` 太软,看着没劲
- **`ease-in` 在界面上是禁用的** —— 它起步慢,点下去像卡了一下
- 位移、缩放、手势跟随可以用弹簧;透明度和颜色用曲线

一个成熟的界面里,同一条曲线会覆盖九成以上的过渡。曲线混用会让整体"手感不统一",
但很难指出具体是哪里不对。

## 具体数值

| 交互 | 值 |
| --- | --- |
| 卡片悬停抬起 | `translateY(-1px)` + 阴影升一档 |
| 按钮按下 | `scale(0.97)`,80ms |
| 卡片按下 | `scale(0.98)` |
| 大卡片按下 | `scale(0.995)` |

**按下的缩放幅度与元素大小成反比** —— 大卡片缩 3% 会显得整个塌下去。

同一条 transition 里,**位移和阴影的时长要比颜色长**:

```css
transition:
  border-color 120ms var(--ease-out),
  box-shadow 160ms var(--ease-out),
  transform 160ms var(--ease-out);
```

## 几条硬规则(不随主题豁免)

- **绝不要从 `transform: scale(0)` 开始**。从 `scale(0.9)` 以上配 `opacity: 0`
- **只动 `transform` 和 `opacity`**。动 `width`/`height`/`top` 会触发重排
- 折叠展开用 `grid-template-rows: 0fr → 1fr`,不用 height —— 不需要 JS 测量
- 列表入场错开 `--index * 80ms`,但**最多错开 6 个**,再多整个列表会拖沓
- 动效不能阻塞高频任务或掩盖操作结果

## 减少动态效果

```css
@media (prefers-reduced-motion: reduce) { … }
```

不是可选的礼貌 —— 这类动效是前庭不适的常见触发源。
但**保留信号**:把位移换成一次颜色或轮廓的变化,别把反馈整个删掉。
