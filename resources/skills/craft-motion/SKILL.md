# 动效方向

**先读 StyleBrief。** 运动强度、时长、缓动、位移和缩放应表达项目的气质与内容节奏；
下面只在方向未明确时提供 fallback 原则，不是一套可复制的手感配方。

## 先问该不该动

有实证:关于"动画帮助理解"的研究,把对照组做严格之后,动画**并不优于静态图**。
唯一站得住的用途是**实时的空间或时间重定向** —— 页面切换、容器展开、
视角变化、进度反馈。

所以:**用户在空间、时间或状态中移动时才动**。
不要为了"教会他""显得高级""填补沉默"而动。

## 时长与节奏

| 范围 | 用途                                                 |
| ---- | ---------------------------------------------------- |
| 短促 | 按下、切换、悬停等即时反馈，应让用户立刻感到响应     |
| 中等 | 弹层、抽屉、下拉等局部空间变化，可留出看清关系的时间 |
| 较长 | 跨屏转场、容器变形或分阶段叙事；避免让高频任务等待   |

进出场是否对称、节奏是轻快还是舒展，都由 StyleBrief 决定；无方向时优先保证反馈及时且不
阻塞下一步操作。

## 缓动与一致性

从 StyleBrief 选取合适的缓动语言，并在同类交互中保持一致。位移、缩放、手势跟随可使用
弹簧或曲线；透明度与颜色也可选择更适合品牌节奏的曲线。关键是交互开始要及时，用户不能
把缓动误解为卡顿。

## 强度与实现

悬停、按下、进场和退出可采用位移、缩放、阴影、透明度或颜色变化。强度、方向和组合由
StyleBrief 决定；没有方向时，从小幅、可感知但不抢内容的变化开始，并在真机/预览中验证。
大型元素通常需要比小控件更克制的几何变化，避免造成空间塌陷。

## 不随主题改变的护栏

- 动效不能阻塞高频任务或掩盖操作结果；反馈应在用户可感知的及时范围内出现。
- 优先使用不会造成不必要布局抖动的实现，并在展开、收起与列表变化时验证性能。
- 遵守减少动态偏好；把空间运动减少为颜色、轮廓或其他可访问的状态信号，而不是删掉反馈。

## 减少动态效果

```css
@media (prefers-reduced-motion: reduce) { … }
```

不是可选的礼貌 —— 这类动效是前庭不适的常见触发源。
但**保留信号**:把位移换成一次颜色或轮廓的变化,别把反馈整个删掉。
