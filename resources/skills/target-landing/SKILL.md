# 落地页

一个落地页只做一件事:让一类明确的人,做一个明确的动作。写第一行代码之前,
这两个空必须填上——填不上就先问(见下)。

## 开工前:判读与提问

先用一句话输出你的判读:「这页给〈谁〉看,让他〈做什么〉,用〈什么证据〉推动行动。」
判读里有空填不上、且 brief 里确实没有,才问;**最多问一次**,用 ask_user,
一次不超过 3 题,每题给选项:

1. **主行动**:注册试用 / 下载 / 预约演示 / 加入等待名单 / 联系销售
2. **受众**:开发者 / 企业决策者 / 普通消费者 / 内部同事
3. **核心证据**:产品能力 / 客户案例 / 真实数据 / 现场活动信息

用户话里带了信号就追对应的问,别问通用问卷:

| 用户提到     | 追问                                                  |
| ------------ | ----------------------------------------------------- |
| 定价、付费   | 几个档位?有没有年付折扣?(这决定要不要对比表)          |
| 数据、成绩   | 有真实数字吗?没有就用诚实占位,**不编**                |
| 竞品、对比   | 允许点名吗?不允许就做"有/无我们"的对比,不出现对方名字 |
| 多语言、出海 | 主语言是哪种?中英文排版规则不同                       |

## 页面结构路线

页面结构不决定视觉。
先激活 design-seed 生成项目主题。下表只列各页面类型需要回答的内容问题，不是固定
版面、区块顺序或视觉母版；实际信息层级由内容和转化路径决定，视觉实现由 StyleBrief 决定。

| 类型      | 必须回答的内容问题                         |
| --------- | ------------------------------------------ |
| 产品官网  | 核心价值、关键能力、可信证据、下一步行动   |
| 等待名单  | 为什么值得等待、需要提交什么、后续会发生什么 |
| 定价页    | 档位差异、适用对象、购买疑虑、购买入口     |
| 活动/发布 | 时间地点、内容安排、参与价值、报名方式     |

## 视觉来源边界

页面类型只决定内容任务，不推导版式气质、首屏形态、字体、背景、圆角、色彩或动效。这些
视觉决定只能来自项目 StyleBrief，并通过 design-seed 的语义 token 落地。若项目尚无
StyleBrief，只使用上游 prompt 在首次确认后给出的六维 fallback；本 target 不自建 fallback，
也不轮换候选样式或以历史项目样式决定当前项目。

## 硬规则

- 主 CTA 全页使用一致措辞；出现位置取决于转化路径，视觉样式服从 StyleBrief。
- 首屏 h1 ≤16 个汉字(英文 ≤9 词),说用户得到什么,不说"我们是谁"。
- 社会证明只用拿得出手的:有真 logo/真数据就放,没有就整段删掉,**不摆假 logo 墙**。
- 文案全部具体到这一个产品。写完通读一遍:任何一句换个产品名也成立的话,重写。

## 交付前自查(全过才算完成)

- [ ] 主行动是不是只有一种措辞，出现位置是否服务转化路径?
- [ ] 页面结构是否由内容层级决定，而非复制固定区块顺序?
- [ ] 搜一遍数字:每个数字要么有出处,要么是 `—` 占位。有一个编的都不行
- [ ] 把首屏截给项目外的人看:能看出这是**什么产品**吗?看不出就是模板,重写首屏文案
