# 配色手艺

## 调色板是四层,按**占屏比例**分配

先想清楚四层再写 CSS。

| 层 | 占多少像素 | token |
| --- | --- | --- |
| **中性色** | **70–90%** | `--bg` `--surface` `--fg` `--muted` `--border` |
| **强调色**(一个) | 5–10% | `--accent` —— **不要发明第二个** |
| 语义色 | 0–5% | `--success` `--warn` `--danger` |
| 效果 | <1% | 渐变、辉光。很少有正当理由 |

**看着"花"几乎总是这个比例失衡。** 不是颜色选得不好。

## 强调色纪律

AI 产出最大的可读性问题就是强调色泛滥。硬上限:

- **一屏最多出现 2 处**可见的 `--accent`。典型搭配:一个眉标/标签 + 一个主按钮
- **链接算强调色**。同屏已经有主按钮时,链接降级为 `--fg` + 下划线
- **悬停态和焦点环也算**。按这个额度分配

## 中性色不要都在同一根色相轴上

这是"廉价"和"贵"之间最大的一个差别,而且几乎不花成本:

- **抬起来的表面和文字走暖**(色相 ~40°)
- **凹下去的填充和所有描边走冷**(色相 ~215°)

暖纸配冷发丝线。全部用同一个灰的话,界面会平得像张纸板。

## 没有纯黑纯白

| token | 亮色 | 暗色 |
| --- | --- | --- |
| 背景 | `#fafafa`(不是 `#fff`) | `#0f0f0f`(不是 `#000`) |
| 前景 | `#111111`(不是 `#000`) | `#f0f0f0`(不是 `#fff`) |

纯黑纯白在屏幕上会"震",长时间看眼睛累。

暗色表面上**用半透明白描边**而不是实色深描边:`1px rgba(255,255,255,0.08)`
读起来是结构,而实色描边会显脏。

## 派生色只用两个配方

需要一个"带强调色的填充"或"带强调色的描边"时,不要另调一个 hex:

```css
/* 填充:强调色 5–12% 混进面板色 */
background: color-mix(in srgb, var(--accent) 8%, var(--surface));

/* 描边:强调色 22–45% 混进描边色 */
border-color: color-mix(in srgb, var(--accent) 30%, var(--border));
```

**描边的浓度约是填充的 4 倍。** 记住这个比例,所有的提示条、选中态、激活标签
就会自动一致,而且换主题时自动跟着变——因为混合的目标本身是 token。

## token 按用途命名,不按色相

```css
--accent: #2f6feb;    /* ✅ 用途 */
--blue-500: #2f6feb;  /* ❌ 色相 —— 以后想换成绿色就得改所有引用 */
```

## 必须避开的默认值

- **Tailwind 的靛蓝** —— `#6366f1` `#4f46e5` `#4338ca` `#8b5cf6` `#7c3aed` `#a855f7`。
  **这是最可靠的 AI 破绽**,一眼就能认出来
- **首屏的双色渐变**(紫→蓝、蓝→青、靛→粉)。第二可靠的破绽。
  **一个平面 + 一套有层次的字排,任何时候都比它强**
- **没有功能的装饰性渐变**。渐变应该用来分隔层级(页头/正文、主/次按钮),
  不是用来填充空白
