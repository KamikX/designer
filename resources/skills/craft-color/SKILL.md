# 配色手艺

先读 StyleBrief。以下所有具体比例、色温、材质、色值和反模式只是方向未明确时帮助建立
层级的 fallback 建议；明确的品牌色、暗色、高对比或极简要求优先，只要不牺牲可访问性和
状态语义。

## 调色板是四层,按**占屏比例**分配

先想清楚四层再写 CSS。

| 层         | 占多少像素 | token                                                                                                                |
| ---------- | ---------- | -------------------------------------------------------------------------------------------------------------------- |
| **中性色** | **70–90%** | `--color-bg` `--color-surface` `--color-raised` `--color-sunken` `--color-ink` `--color-ink-muted` `--color-line` `--color-line-strong` |
| **强调色** | 5–10%      | `--color-brand-500` `--color-brand-600` `--color-focus`                                                              |
| 语义色     | 0–5%       | `--color-success` `--color-warning` `--color-danger` `--color-info`                                                  |
| 效果       | <1%        | 渐变、辉光。很少有正当理由                                                                                           |

当界面显得杂乱时，可先检查这些比例是否失衡；它们不是固定配色公式。

## 强调色层级

按 StyleBrief 决定强调色的数量、分布和强度。检查主操作、链接、选中态与焦点环是否各自
有可理解的语义和足够对比度；当多个高饱和元素竞争注意力时，再把这视为需要收敛的信号。

## 中性色层级

表面层级可以通过多种手段建立:

- 可以用明度、色相、边框、纹理或阴影区分表面；暖表面配冷描边只是其中一种可选手法。
- 若全部使用同一中性色，仍需确保层级、边界和交互状态易于辨认。

## 高对比的黑白选择

| token | 亮色                   | 暗色                   |
| ----- | ---------------------- | ---------------------- |
| 背景  | `#fafafa`(不是 `#fff`) | `#0f0f0f`(不是 `#000`) |
| 前景  | `#111111`(不是 `#000`) | `#f0f0f0`(不是 `#fff`) |

纯黑或纯白可以是品牌、无障碍或极简风格的有意选择；使用时检验眩光、阅读舒适度和相邻
层级，而不是把颜色本身视为禁忌。

暗色表面可尝试半透明描边来维持结构；实色边界、无边界或其他材质也可成立，只需验证对比度。

## 派生色示例

需要一个"带强调色的填充"或"带强调色的描边"时，可用 token 派生，而非新增孤立色值:

```css
/* 填充:强调色 5–12% 混进面板色 */
background: color-mix(in srgb, var(--color-brand-500) 8%, var(--color-surface));

/* 描边:强调色 22–45% 混进描边色 */
border-color: color-mix(in srgb, var(--color-brand-500) 30%, var(--color-line));
```

描边与填充的相对浓度应由 StyleBrief 的表面语言和可读性决定；以上只是能随 token
变动的一种写法。

## token 按用途命名,不按色相

```css
--color-brand-500: #2f6feb; /* ✅ 品牌交互用途 */
--color-blue-500: #2f6feb; /* ❌ 色相 —— 以后想换成绿色就得改所有引用 */
```

## 常见模板化倾向（fallback 检查）

- Tailwind 的靛蓝与首屏双色渐变容易在无明确方向时产生模板感；若 StyleBrief 明确选择，
  将它们映射为项目 token，并验证层级、对比度和内容意图。
- 没有功能的装饰性渐变值得重新评估；渐变也可以是项目的品牌语言或层级线索。
