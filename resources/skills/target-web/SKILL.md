# PC Web 应用

Web 应用和落地页的根本区别:落地页给人**看**,应用给人**用**。本 target 只约束
工作区结构、交互状态与可访问性，不决定视觉气质；具体的装饰程度、表面语言与布局尺度
全部服从项目 StyleBrief。

## 开工前:判读与提问

判读一句话:「核心对象是〈什么〉,用户主要在〈哪种工作区〉里〈做什么〉。」
缺关键信息才问,最多一次,不超过 3 题:

1. **核心对象**:文档 / 任务 / 媒体 / 数据记录 / 会话
2. **工作区形态**:列表+详情 / 导航+列表+详情 / 画布 / 编辑器
3. **交互约束**:是否依赖键盘、批量操作、拖拽或实时协作

信号追问:

| 用户提到   | 追问                                                |
| ---------- | --------------------------------------------------- |
| 协作、团队 | 要不要体现在线状态/头像?多人编辑冲突怎么提示        |
| 搜索       | 全局搜索(⌘K 风格)还是列表内筛选?                    |
| 拖拽、排序 | 拖拽中的视觉反馈与放置指示怎么做,占位符要不要       |
| 大量数据   | 上万条走虚拟滚动语义:固定行高 + 分页/无限加载二选一 |

## 布局路由

| brief 里出现             | 用                                              |
| ------------------------ | ----------------------------------------------- |
| 收件箱、任务、工单、客服 | 列表 + 详情,列表项有已读/选中态                |
| 文档、笔记、知识库       | 导航 + 目录树 + 编辑区                         |
| 看板、项目               | 顶栏 + 水平滚动列,卡片可拖拽                    |
| 画布、设计、流程图       | 全屏画布 + 浮动工具条 + 可收起属性面板          |
| 会话、聊天、AI           | 侧栏会话列表 + 主区消息流 + 底部输入框          |

## 视觉来源边界

工作区形态只回答信息如何组织，不推导侧栏、密度、卡片、明暗、品牌色、字体、圆角或动效。
这些视觉决定只能来自项目 StyleBrief，并通过 design-seed 的语义 token 落地。若项目尚无
StyleBrief，只使用上游 prompt 在首次确认后给出的六维 fallback；本 target 不自建 fallback，
也不轮换候选样式或以历史项目样式决定当前项目。

## 硬规则

- **每个可点元素都有可感知的 hover 与 focus-visible 态**，表现方式服从 StyleBrief。
- 键盘可用:Tab 顺序合理,列表支持 ↑↓ 移动选中;做全局搜索就配 ⌘K。
- 导航当前项要有明确且可访问的指示，具体表现服从 StyleBrief。
- 主操作与次级操作保持清晰的语义层级，颜色、表面和尺寸服从 StyleBrief。
- 行内操作(编辑/删除)hover 才浮现,但**触屏兜底**:不要让功能只藏在 hover 里。
- 空态、加载骨架、错误重试三态齐全;表格与列表的数字按字段语义对齐。
- 首屏必须提供可执行的核心工作流，不用纯宣传内容取代功能入口。

## 交付前自查

- [ ] 拔掉鼠标走一遍:纯键盘能到达并触发每个主要操作吗?
- [ ] 主操作与次级操作是否层级清楚，且视觉表达与 StyleBrief 一致?
- [ ] 新用户第一次打开(零数据)看到的是引导性空态,还是一片惨白?
- [ ] 界面上有没有一句话是"说给访客听的"?有就删——用户已经在用了,不需要被推销
