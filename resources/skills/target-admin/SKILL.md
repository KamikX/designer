# 中后台

中后台的美学只有一条:**信息密度就是功能**。运营同学一天看八小时,
装饰的每一个像素都在浪费他的屏幕。克制到近乎无趣,才是对的。

## 开工前:判读与提问

判读一句话:「管理的核心实体是〈什么〉,关键字段是〈哪几个〉,数据量级〈多大〉。」
缺关键信息才问,最多一次,不超过 3 题:

1. **核心实体与字段**:列表页每行到底显示什么?(名称/状态/金额/时间/操作人…)
2. **数据量级**:几十条(不用分页) / 几千条(分页+筛选) / 更多(筛选是主入口,默认不全量列出)
3. **要不要角色**:单角色 / 多角色(界面上体现权限差异:按钮禁用还是隐藏)

信号追问:

| 用户提到 | 追问 |
| --- | --- |
| 审核、工单 | 批量操作要不要?通过/驳回是否必填理由 |
| 报表、统计 | 看趋势还是看对比?图表跟着问题选,不是先选图表 |
| 导入导出 | 什么格式?出错行怎么反馈(逐行报错,不是"导入失败") |
| 状态、流程 | 把状态机列出来:每个状态什么颜色、能流转到哪、谁能操作 |

## 页面路由

| brief 里出现 | 用 |
| --- | --- |
| 列表、管理、查询 | 列表页:筛选区 + 表格 + 分页;行操作 ≤3 个,多的收进「···」 |
| 详情、审核 | 详情页:头部摘要卡 + 分组字段;操作按钮固定在头部右侧 |
| 新建、编辑、配置 | 表单页:单列 ≤7 项直接放,更多就分组;失焦校验,提交兜底 |
| 概览、大盘、数据 | 看板页:顶部 3–4 个指标卡 + 一主一辅两张图 + 异常列表 |

## 风格维度:每一项都要做选择,别每次都默认同一组

克制 ≠ 千篇一律。信息架构收敛,但下面这些维度是**设计决策**,判读时逐项声明
(「导航〈左侧栏〉,表格〈紧凑〉,卡片〈描边〉,主题〈浅色〉,品牌色注入〈导航〉」),
用户给了偏好听用户的;没给就按 brief 选,**不要连续两个项目选同一组**:

| 维度 | 选项 |
| --- | --- |
| 导航形态 | 左侧栏(默认,菜单多) / 顶部导航(层级浅、页面少) / 双栏(模块多且每模块子项多) |
| 表格密度 | 紧凑(运营整天用) / 舒适(低频使用、字段少) |
| 卡片风格 | 描边卡片 / 无边框平铺 + 分割线(更利落,密度更高) |
| 明暗 | 浅色(默认) / 深色(监控大屏、开发者工具) |
| 品牌色注入位置 | 当前导航项 + 主按钮(默认) / 深色侧栏整条用品牌色调 / 顶栏细条 |

品牌色本身按 design-seed 的规则定(用户方向优先,占位色必换)。

## 硬规则

- 结构骨架:导航(按上表选形态) + 顶栏 + 内容区 `bg-bg`,卡片 `bg-surface`;
  左侧栏形态时宽 220px 可折叠。
- 表格:表头 `text-ink-muted` 12px;数字列 `.num` 右对齐;金额带千分位;时间到分钟。
- 状态用**小圆点 + 文字**,不用大色块胶囊;整表状态色种类 ≤4。
- 每个筛选条件都要能**单独清除**,并有"重置全部";筛选后的空结果要说"没有匹配项,
  试试放宽条件",和"还没有任何数据"是两个不同的空态。
- 危险操作(删除、驳回、下线)一律二次确认,确认框里写清楚**后果和影响范围**。
- 表格四态齐全:数据 / 空 / 加载骨架(行状,不是转圈) / 出错可重试。
- 强调色只出现在:主按钮、当前导航项、必要的链接。图表另算(去 craft-color 领预算)。

## 交付前自查

- [ ] 挤得下吗:1440px 宽下,列表页一屏能看到 ≥10 行数据吗?看不到就在浪费密度
- [ ] 数一遍颜色:除状态点和主按钮外,还有别的彩色吗?有就删
- [ ] 每个表格列问一遍:运营靠这列做什么决定?答不上来的列删掉
- [ ] 空态、错误态、加载态三个都真的写了吗?(最常被跳过的就是这里)
