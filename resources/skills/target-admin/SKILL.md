# 中后台

中后台以**运营清晰和效率优先**：信息架构、数据密度和操作反馈必须让高频工作变快；视觉
语言则由项目 StyleBrief 决定，不把某一种克制、明暗、字体或表面当成默认答案。

## 开工前:判读与提问

先读 StyleBrief，它高于本模板的视觉示例。判读一句话:「管理的核心实体是〈什么〉,
关键字段是〈哪几个〉,数据量级〈多大〉，视觉实现如何响应 StyleBrief。」
缺关键信息才问,最多一次,不超过 3 题:

1. **核心实体与字段**:列表页每行到底显示什么?(名称/状态/金额/时间/操作人…)
2. **数据量级**:几十条(不用分页) / 几千条(分页+筛选) / 更多(筛选是主入口,默认不全量列出)
3. **要不要角色**:单角色 / 多角色(界面上体现权限差异:按钮禁用还是隐藏)

信号追问:

| 用户提到   | 追问                                                  |
| ---------- | ----------------------------------------------------- |
| 审核、工单 | 批量操作要不要?通过/驳回是否必填理由                  |
| 报表、统计 | 看趋势还是看对比?图表跟着问题选,不是先选图表          |
| 导入导出   | 什么格式?出错行怎么反馈(逐行报错,不是"导入失败")      |
| 状态、流程 | 把状态机列出来:每个状态什么颜色、能流转到哪、谁能操作 |

## 页面路由

| brief 里出现     | 用                                                       |
| ---------------- | -------------------------------------------------------- |
| 列表、管理、查询 | 列表页:筛选区 + 表格 + 分页;行操作 ≤3 个,多的收进「···」 |
| 详情、审核       | 详情页:头部摘要卡 + 分组字段;操作按钮固定在头部右侧      |
| 新建、编辑、配置 | 表单页:单列 ≤7 项直接放,更多就分组;失焦校验,提交兜底     |
| 概览、大盘、数据 | 看板页:顶部 3–4 个指标卡 + 一主一辅两张图 + 异常列表     |

## StyleBrief 实现检查

保留管理系统的可扫描结构，但逐项把视觉决定回译为 StyleBrief，而不是套模板：

- 导航形态应匹配模块层级、权限范围和 StyleBrief 的几何/表面语言。
- 表格密度在保证一屏决策效率的前提下响应 StyleBrief；列、筛选和操作不因装饰而牺牲。
- 卡片、边界和阴影遵循 StyleBrief 的表面层级，不覆盖用户指定的圆角、字体、色温或材质。
- 明暗模式、品牌色出现位置及状态呈现与 StyleBrief 和 `theme.css` 对齐，同时保留足够对比度。
- 在实现前写明上述选择如何服务运营任务；这份检查不能产生任何固定默认项。

## 硬规则

- 结构骨架:导航 + 顶栏 + 内容区；导航布局和卡片表面由 StyleBrief 实现，并保持高频操作
  可扫描、可访问。
- 表格:表头、数字对齐、金额和时间格式应服务字段扫描；字号、密度与表面按 StyleBrief
  和任务频率决定。
- 状态必须同时具备文字或图标等非色彩线索，并让可执行的下一步清楚可见；呈现形态由
  StyleBrief 与状态机决定。
- 每个筛选条件都要能**单独清除**,并有"重置全部";筛选后的空结果要说"没有匹配项,
  试试放宽条件",和"还没有任何数据"是两个不同的空态。
- 危险操作(删除、驳回、下线)一律二次确认,确认框里写清楚**后果和影响范围**。
- 表格四态齐全:数据 / 空 / 加载骨架(行状,不是转圈) / 出错可重试。
- 品牌强调色按 StyleBrief 和状态语义节制使用；图表另按 craft-color 的可读性预算处理。

## 交付前自查

- [ ] 密度是否让运营人员在其常用视口快速比较、筛选和行动，同时符合 StyleBrief?
- [ ] 品牌色、状态色与表面层级是否各自表达明确用途，并保持足够对比度?
- [ ] 每个表格列问一遍:运营靠这列做什么决定?答不上来的列删掉
- [ ] 空态、错误态、加载态三个都真的写了吗?(最常被跳过的就是这里)
