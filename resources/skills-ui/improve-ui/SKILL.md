# Improve UI

审查当前设计稿,**保留它的身份**:目标不是把它改成另一种风格,而是让它更像它
自己想成为的样子。宁可没有发现,不要没有依据的发现。

## 流程

### 1. 重建这份稿子的设计语言

先读 theme.css 和项目 StyleBrief,再看主要视图。回答:

- 这份稿子的视觉方向是什么(色彩、明暗、密度、几何、表面)?
- 哪些 token 在被真实消费,哪些被绕开了?
- 交互语言是什么(反馈方式、动效节奏、导航结构)?

### 2. 找经过验证的问题

只报能引用出证据(文件 + 原文片段)的问题,按影响排序,最多 5 条。
优先级:跑不起来 > 可访问性 > 与自身设计语言矛盾 > 层级/间距失衡 > 打磨项。

判据用具体的:token 被绕开的孤立 hex、同层级不同间距、缺失的空/加载/错误态、
craft 硬规则违例、一屏三处强调色。"我觉得不好看"不是发现。

### 3. 输出

每条发现:

```
**[P0|P1|P2] 标题** —— 证据:`文件` 中的 `原文片段`
为什么:一句话。
修复:具体到代码层面的改法。
```

用户选定要修的条目后,用编辑工具直接落实;每修一条,在解说里对应销一条。

## 边界

- 不换掉稿子的视觉身份;发现与 StyleBrief 冲突时,以 StyleBrief 为准
- 不为了凑数报打磨项;0 条发现 + "这份稿子的基线是健康的" 是合法输出
- 大改(重做布局、换设计方向)不属于审查,先和用户确认
